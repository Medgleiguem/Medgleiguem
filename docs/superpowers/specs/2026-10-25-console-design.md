# Animated console GitHub profile — design for review

25 October 2026. Status: approved direction with explicit user amendments below; implement the amended desert composition.

## Intent and selected approach

Med selected https://github.com/georgekobaidze as the closest reference and asked for an original spin, better design, larger visual weight and more dynamic animation. The new profile should feel like a professional who uses GitHub daily. Its identity, GitHub activity and tools lead; the substantial institutional work remains accessible without becoming the main-page catalogue. Dark theme, strong anime character and prominent polished animation remain essential.

Three directions were examined together: a cohesive cyan console (Giorgi), a compact green security HUD (thewhiteh4t), and anime artwork with an animated terminal (Bokyerthe). Med chose the first. The compact HUD is too small for the desired richness, while the anime/terminal reference lacks the chosen reference's consistency. This design therefore uses one coherent console composition with original anime illustration. Do not copy the reference's city, code, wording or exact panel layouts.

## Visual design

The concept image shown in the conversation establishes an obsidian ground, silver typography, electric cyan signals and small warm amber accents. Name and key visuals are large. Borders are thin and selective. Avoid badge walls, long biography, education/work chronology and ten project cards. The readme should be substantially shorter than the current approximately 3,200 px desktop layout; aim for 1,300–1,700 px in the actual GitHub column and assess visual density there.

The initial character study had natural black wavy-curly hair and warm tan skin, both explicitly requested by Med. The latest steering supersedes the portrait: remove the face/character and make the desert and Mauritanian visual language the identity. Produce separate clean environment illustration rather than publishing the whole generated mockup as one image. The user likes the dunes, architecture and atmosphere and wants them carried into icons, frames and visual ideas. Do not add claims about where the user lives or builds, slogans about national identity, or extra prose explaining the aesthetic.

Use layered night dunes, small historic ksar silhouettes, sparse pale geometric facade details and an organic concentric contour motif inspired by the Richat Structure. Preserve the dark high-tech/anime-environment art direction. Sand-gold light becomes a strong counterpoint to cyan technical signals. These are artistic allusions, not literal geographic maps or depictions of real institutional facilities. Primary visual grounding: https://whc.unesco.org/en/list/750/ and https://science.nasa.gov/earth/earth-observatory/richat-structure-mauritania-4602/ . Keep technology symbols recognizable; custom manuscript, branch, code and book symbols can share sparse geometric framing.

## Motion design

The result must visibly animate, including when opened midway through a loop. Essential content never depends on watching an animation. Use independently phased motion, with a common visual rhythm:

| Layer | Behavior | Proposed timing |
| --- | --- | --- |
| Header paths | Bright points traverse curved and branching paths over dunes and the sky | 8–12 seconds |
| Orbital detail | Slow arc movement and small tracking lights | 18–24 seconds |
| Dune lighting | Fine moving sand-gold wisps skim selected dune ridges | 6–9 seconds |
| Activity constellation | Several staggered branch signals flow toward the calendar boundary | 8–12 seconds |
| Tool dock | Brief, staggered icon traces, then a readable settled hold | 10–14 seconds |
| Footer | A sparse traveling signal connects the contact area visually | 12–18 seconds |

The environment is illustrated artwork with vector light and signal animation. Do not animate real calendar values into other values, exaggerate counts, or make random simulated events look like live GitHub activity. No repeated whole-screen glitch or rapid flashing. Provide an explicit static mode for reduced-motion users.

## GitHub constraints and builder decisions

The deliverable is a profile README, using supported Markdown/HTML, native links and self-contained animated SVG image assets. There is no JavaScript, arbitrary page CSS, hover-only navigation, interactive canvas or fake functional console. A local webpage is insufficient evidence of GitHub compatibility.

Reuse audited activity collection, privacy boundaries, daily refresh and appropriate checks from the current repository. Change the renderer and README composition. Keep private identifiers out of public aggregates. Keep existing briefs available through a compact work index. Do not modify unrelated VulnClaw files.

Use separate mobile compositions and explicit reduced-motion assets through picture sources. At 390 px and 320 px, simplify illustration/decoration, stack the dock, and keep essential labels readable. Target a desktop rendered text size of at least 16 px for essential labels; avoid a fixed desktop canvas shrunk into a phone. Mirror image content in meaningful alt text and native link/text context. Essential links must remain individual clickable native elements, not regions baked into a raster.

Proposed budget: under 3 MB of initially loaded image assets per viewport and under 2 MB per individual SVG; measure rather than assume. Use a separate optimized illustration with controlled crop and vector overlays. The builder chooses exact path geometry, compression, typographic implementation, frame spacing and source organization. Build meaningful static base states before motion; avoid invisible-first animation that can leave content missing.
